# Продуктовая спецификация: Wildberries API Bundle

## Обзор

**BaksDev Wildberries Bundle** — это Symfony-бандл, предоставляющий интеграцию с API Wildberries для управления товарами, заказами, остатками и продажами. Бандл реализует паттерн Domain-Driven Design (DDD) и следует принципам чистой архитектуры.

- **Версия:** 7.4.9 (git tag; в composer.json версия не декларируется)
- **Тип:** Symfony Bundle / Composer Package
- **Лицензия:** MIT
- **Требования:** PHP 8.4+, baks-dev/core ^7.4 (Symfony 7.4+ подтягивается транзитивно через core)

---

## Цель продукта

Предоставить разработчикам готовый модуль для интеграции с Wildberries Marketplace API, который позволяет:

- Управлять токенами авторизации для разных профилей пользователей
- Получать данные о складах, остатках, заказах и продажах
- Работать со справочниками категорий, характеристик и конфигураций карточек
- Автоматизировать обновление данных через Message Bus
- Кешировать результаты запросов для снижения нагрузки на API

---

## Целевая аудитория

1. **Разработчики Symfony** — создают интернет-магазины и системы управления товарами
2. **Администраторы магазинов** — управляют токенами доступа и настройками интеграции
3. **Системные администраторы** — настраивают обработчики сообщений и cron-задачи

## Основные функции

### 1. Управление токенами авторизации

Система хранит и управляет токенами Wildberries для разных профилей пользователей.

**Сущности:**
- `WbToken` — основная запись токена
- `WbTokenEvent` — событие изменения токена (audit trail)
- `WbAuthorizationToken` — объект авторизации для API-вызовов

**Поля токена:**
- Статус (активен/заблокирован)
- Профиль пользователя
- Токен доступа (строка)
- Торговая наценка (процент или сумма)
- Настройки подключения:
  - Обновление карточек
  - Обновление остатков
  - Обновление заказов
  - Обновление продаж
  - Идентификатор склада

### 2. Работа с API Wildberries

Бандл предоставляет абстракции для всех основных API Wildberries:

| API | Домен | Назначение |
|-----|-------|------------|
| `suppliers-api.wildberries.ru` | Основной | Работа с товарами, заказами, остатками |
| `content-api.wildberries.ru` | Контент | Управление карточками товаров |
| `marketplace-api.wildberries.ru` | Маркетплейс | Склады, информация о товарах |
| `discounts-prices-api.wildberries.ru` | Цены | Скидки и цены |
| `feedbacks-api.wildberries.ru` | Отзывы | Управление отзывами |
| `seller-analytics-api.wildberries.ru` | Аналитика | Отчеты продавца |
| `statistics-api.wildberries.ru` | Статистика | Детальная статистика |
| `buyer-chat-api.wildberries.ru` | Чат | Сообщения покупателей |

**Пример использования:**

`Wildberries` — абстрактный базовый класс, напрямую инстанцировать его нельзя; методы выбора домена (`marketplace()`, `content()` и т.д.) — protected и используются внутри конкретных классов:

```php
$warehouses = new ProfileWarehousesRequest(...);

foreach ($warehouses->profile($profileUid)->warehouses() as $warehouse) {
    echo $warehouse->getId() . ': ' . $warehouse->getName();
}
```

### 3. Справочники

**Object (Категории):**
- Метод: `/content/v2/object/all`
- Получение списка всех категорий товаров

**Characteristics (Характеристики):**
- Метод: `/content/v1/object/characteristics/{name}`
- Характеристики для создания КТ в подкатегории

**ConfigCard (Конфигурация карточек):**
- Метод: `/api/v1/config/get/object/translated`
- Конфигурация обязательных полей для карточек

**Warehouses (Склады):**
- Метод: `/api/v3/warehouses`
- Список складов продавца

### 4. Асинхронная обработка

Используется Symfony Messenger для обработки событий:

- `WbTokenMessage` — обновление токена
- `WildberriesMessage` — общие сообщения API

Очередь: `wildberries`

### 5. Кеширование

Реализовано на уровне Symfony Cache:
- FilesystemAdapter для кеширования справочников
- TTL: 24 часа (категории, характеристики, конфигурация карточек)

## Пользовательские сценарии

### Сценарий 1: Настройка токена Wildberries

**Актор:** Администратор

1. Переходит в раздел "Wildberries" → "Токены"
2. Нажимает "Создать токен"
3. Заполняет форму:
   - Выбирает профиль пользователя
   - Вводит токен доступа
   - Настраивает флаги обновления (карточки, остатки, заказы, продажи)
   - Указывает склад и наценку
4. Сохраняет настройки

**Результат:** Токен сохраняется в БД и становится доступен для API-вызовов.

### Сценарий 2: Получение списка складов

**Актор:** Система / Разработчик

```php
$warehouses = new ProfileWarehousesRequest(...);
$warehouses->profile($profileUid);

foreach ($warehouses->warehouses() as $warehouse) {
    echo $warehouse->getId() . ': ' . $warehouse->getName();
}
```

**Результат:** Генератор объектов складов.

### Сценарий 3: Получение категорий товаров

**Актор:** Система

```php
$category = new WbObject(...);
$category->profile($profileUid);

foreach ($category->findObject() as $object) {
    echo $object->getName();
}
```

**Результат:** Кешированный список категорий.

### Сценарий 4: Обновление карточки товара

**Актор:** Система (через Message Bus)

1. Создается команда `WbTokenDTO` с изменениями
2. Команда обрабатывается `WbTokenHandler`
3. Создается событие `WbTokenEvent`
4. Сообщение `WbTokenMessage` отправляется в очередь `wildberries`
5. Обработчик `WbTokenDispatch` принимает сообщение (на текущий момент реализация пуста — обновление данных на Wildberries по событию еще не выполняется)

## Структура данных

Схема «звезда»: таблица `wb_token_event` хранит только идентификаторы, каждое поле события — отдельная сущность со своей таблицей (OneToOne к событию).

### Таблица `wb_token`

| Поле | Тип | Описание |
|------|-----|----------|
| id | WbTokenUid | ID токена (UUID) |
| event | WbTokenEventUid | ID последнего события |

### Таблица `wb_token_event`

| Поле | Тип | Описание |
|------|-----|----------|
| id | WbTokenEventUid | ID события (UUID) |
| main | WbTokenUid | ID токена |

### Таблицы полей события (первичный ключ — `event`)

| Таблица | Тип `value` | Описание |
|---------|-------------|----------|
| `wb_token_profile` | UserProfileUid | Профиль пользователя |
| `wb_token_value` | WbTokenString | Токен доступа |
| `wb_token_active` | bool | Статус (активен/заблокирован) |
| `wb_token_percent` | string | Торговая наценка |
| `wb_token_card` | bool | Флаг обновления карточек |
| `wb_token_stocks` | bool | Флаг обновления остатков |
| `wb_token_orders` | bool | Флаг обновления заказов |
| `wb_token_sales` | bool | Флаг продаж |
| `wb_token_warehouse` | string | ID склада |

### Таблица `wb_token_modify`

Метаданные изменения (audit): `event` (PK), `action`, `mod_date`, `usr`, `ip`, `agent`.

## Безопасность

### Роли доступа

- `ROLE_WB_TOKEN` — доступ к управлению токенами Wildberries

### Входные точки

- `/admin/wb/tokens/{page}` — список токенов (`wildberries:admin.index`)
- `/admin/wb/token/new` — создание токена (`wildberries:admin.newedit.new`)
- `/admin/wb/token/edit/{id}` — редактирование токена (`wildberries:admin.newedit.edit`)
- `/admin/wb/token/delete/{id}` — удаление токена (`wildberries:admin.delete`)

### Валидация

- Токен — обязательное поле
- Профиль — обязательное поле
- UUID-валидация для всех идентификаторов
- Валидация связанных DTO-объектов

## Нефункциональные требования

### Производительность

- Кеширование справочников снижает количество запросов к API
- Результаты кешируются на 24 часа

### Масштабируемость

- Поддержка множества профилей пользователей
- Асинхронная обработка через Messenger
- Возможность горизонтального масштабирования

### Надежность

- Retry-логика для HTTP-запросов (RetryableHttpClient)
- Обработка ошибок с логированием
- Транзакционность при сохранении событий

### Поддерживаемость

- PSR-4 автозагрузка
- Строгая типизация (declare(strict_types=1))
- PHPDoc комментарии
- Unit-тесты
